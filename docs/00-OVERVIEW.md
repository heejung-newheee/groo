# 00. 서비스 개요

## 한 줄 정의

**내가 키우는 식물의 성장을 사진으로 기록하고, AI에게 상태를 물어볼 수 있는 개인 식물 다이어리.**

## 문제 정의

식물을 키우는 사람들이 실제로 겪는 것:

1. **기억이 안 난다** — "마지막으로 물 준 게 언제였지?"
2. **성장이 체감 안 된다** — 매일 보면 변화를 못 느낀다. 3개월 전 사진과 비교해야 안다.
3. **문제가 생겨도 뭔지 모른다** — 잎이 노래졌는데 물 부족인지 과습인지 햇빛인지 모른다.
4. **사진은 갤러리에 흩어져 있다** — 식물별로 모아서 볼 방법이 없다.

## 해결 방식

| 문제 | 해결 |
|---|---|
| 기억 안 남 | 활동 태그(물주기/분갈이/비료…) + 물주기 주기 알림 |
| 성장 체감 안 됨 | 식물별 타임라인 + Before/After 비교 + D+일수 |
| 문제 진단 불가 | AI가 사진 보고 관찰·의심 증상·권장 조치 제시 |
| 사진 흩어짐 | 식물 단위로 사진 자동 그룹핑, EXIF 촬영일 자동 정렬 |

## 타겟 사용자

**주 타겟** — 실내에서 화분 3~15개를 키우는 20~40대

- 식물에 애착이 있지만 전문 지식은 없다
- 인스타에 식물 사진을 올리지만 체계적 기록은 안 한다
- "얘가 왜 이러지?"를 검색해도 답이 제각각이라 답답하다

**비타겟 (지금은)**

- 농업/원예 전문가 (요구 수준이 다름)
- 텃밭·노지 재배 (날씨/토양 등 변수가 완전히 다름)

## 핵심 가치 3가지

1. **기록의 마찰이 없다** — 사진 고르면 날짜가 자동으로 채워진다. 3탭이면 저장 끝.
2. **성장이 눈에 보인다** — D+일수와 타임라인이 애착을 만든다.
3. **혼자가 아니다** — 막힐 때 물어볼 대상이 앱 안에 있다.

## 성공 지표 (MVP 기준)

| 지표 | 목표 |
|---|---|
| 가입 후 7일 내 일지 3건 이상 작성 | 40% |
| 주 1회 이상 재방문 (4주차) | 30% |
| AI 진단 "도움됐어요" 비율 | 70% |
| 일지 작성 완료율 (시작 → 저장) | 85% |

## 플랫폼 전략

```
반응형 웹 + PWA   → 스토어 심사 없이 즉시 배포, 비용 0
                   홈화면 추가로 앱처럼 사용, iOS 16.4+ 웹 푸시
```

**웹으로 기획하고 웹으로 끝낸다.** 네이티브 앱이 정말 필요해지는 시점이 오면
그때 별도 프로젝트로 새로 만든다. Supabase(스키마·RLS·Auth·Storage)는 그대로 재사용된다.

WebView로 감싼 앱은 App Store 심사 가이드라인 4.2(Minimum Functionality) 리젝 위험이 크므로
선택지에서 제외한다.
