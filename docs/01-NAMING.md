# 01. 네이밍

## 질문: "그루"는 나무 단위인데, 나는 화분을 키운다. 괜찮을까?

### 사실관계

표준국어대사전상 **"그루"는 나무를 세는 단위**가 맞다.
초본식물(풀)을 셀 때는 "포기"를 쓴다. 엄밀히는 어긋난다.

### 그럼에도 큰 문제가 아닌 이유 3가지

1. **실내 화분 인기종 상당수가 실제로 목본(나무)이다.**
   고무나무, 벵갈고무나무, 떡갈고무나무, 파키라, 벤자민, 아보카도, 올리브, 커피나무 —
   "화분 식물 = 풀"이라는 전제가 애초에 틀렸다.

2. **브랜드명은 고유명사화된다.**
   카카오, 쿠팡, 배민 모두 원래 뜻과 서비스 내용이 직접 연결되지 않는다.
   사용자는 "그루"를 앱 이름으로 인식하지, 국어사전을 찾아보지 않는다.

3. **카운팅 단위로만 안 쓰면 된다.**
   "3그루 키우는 중" 대신 "나의 초록이 3"처럼 쓰면 어색함 자체가 사라진다.
   이름은 그대로 두고 카피만 조정하면 되는 문제다.

### 결론

**그루를 그대로 써도 된다.** 단, UI 카피에서 "N그루"라는 표현은 피한다.

## 그래도 바꾸고 싶다면 — 대안 3

세 가지 모두 **식물 종류를 가리지 않고**, 2~3음절이며, 카피가 풍부하게 나오는 이름이다.

### 1. 자람 (Jaram) — 가장 추천

> "자라다"의 명사형. 이 앱의 주제 그 자체.

| 항목 | 내용 |
|---|---|
| 강점 | 나무/풀/다육 무관. **기록 앱의 본질(성장)과 정확히 일치**. 2음절, 발음 부드러움 |
| 영문 | Jaram — 외국인도 읽기 쉬움 |
| 약점 | "그루"보다 구체적 이미지가 약함 (추상명사) |

**카피 예시**
- 태그라인: **"오늘의 자람을 남기세요"**
- 빈 화면: "아직 기록된 자람이 없어요"
- 타임라인 헤더: "지난 182일의 자람"
- 알림: "몬스테라의 자람을 기록한 지 2주가 지났어요"
- 공유 문구: "우리 집 몬스테라, 이만큼 자랐어요 🌱 #자람"

### 2. 새순 (Saesoon)

> 새로 돋아나는 어린 싹. 모든 식물에 공통으로 존재.

| 항목 | 내용 |
|---|---|
| 강점 | 시각 심볼이 명확(새싹 아이콘 = 로고 직결). 성장·희망의 정서. 종류 무관 |
| 영문 | Saesoon / Sesoon |
| 약점 | "새싹" 계열 앱·브랜드가 많아 차별화가 덜함 |

**카피 예시**
- 태그라인: **"작은 새순부터, 함께"**
- 새 식물 등록: "새순을 들였어요"
- 성장 배지: "첫 새순이 났어요!" (AI가 새 잎 감지 시)

---

### 3. 한뼘 (Hanppyeom)

> 성장을 재는 신체 단위. 정겹고 한국적.

| 항목 | 내용 |
|---|---|
| 강점 | **성장의 "측정"이라는 앱 기능과 직결**. Before/After 비교 기능과 찰떡 |
| 영문 | Hanppyeom — 표기가 길고 어려움 ❌ |
| 약점 | 3음절, 영문 확장성 낮음 |

**카피 예시**
- 태그라인: **"한 뼘씩, 매일 자라요"**
- 비교 화면: "3개월 동안 한 뼘 자랐어요"
- 주간 리포트: "이번 주, 한 뼘만큼의 기록"

## 탈락시킨 후보

| 후보 | 탈락 사유 |
|---|---|
| **포기** | 초본 세는 단위로 의미는 정확하나, **"포기하다"와 동음이의어**. 식물 키우기 앱에서 치명적 |
| **모종** | 귀엽고 화분 친화적이나 "모종의(某種)"와 동음이의 |
| **분(盆)** | 화분 세는 원예 단위로 정확하나, 사람 세는 "분"과 혼동. 1음절이라 브랜드 약함 |
| **화분일기** | 검색 노출은 좋으나 일반명사 조합이라 **상표 등록이 어렵고** 확장성 없음 |
| **Sprouty** | 흔한 조합, 해외 상표 충돌 가능성 높음 |

## 이름을 바꾸려면 (2분 작업)

현재 `그루/groo`로 코드가 작성되어 있다. 변경 시 고쳐야 할 곳:

```bash
# 1. 폴더명
mv /Users/heejungyoo/Desktop/study/groo /Users/heejungyoo/Desktop/study/jaram

# 2. package.json의 "name"
# 3. index.html의 <title>
# 4. 브랜드 문자열 상수 1곳
# 5. docs/ 내 문서 (문자열 치환)
```

문자열이 한곳(`src/lib/constants.ts`의 `BRAND`)에 모여 있으므로 실제 코드 변경은 1파일이다.
